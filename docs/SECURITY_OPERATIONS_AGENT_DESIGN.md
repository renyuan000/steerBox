# 安全运营智能体设计

## 文档定位

安全运营智能体是可以 7x24 常驻运行的安全分析、调查、验证和受控处置系统。它支持用户随时通过聊天接入后台运行中的任务，但聊天只是控制和协同入口，不是唯一运行入口。

本文是长期领域设计，不代表完整安全运营闭环已在 Phase 1 实现。

## 持续输入

计划接入并保留来源、时间、租户、权限和置信度的信号包括：

- 主机、网络、应用和身份日志；
- 告警、检测规则结果和资产变化；
- 漏洞、补丁、暴露面和配置情报；
- 恶意样本摘要、后门线索、病毒指标和 APT 相关情报；
- 安全评估与漏洞研究智能体的验证结果；
- 用户报告、工单、聊天上下文和人工调查结论。

外部情报必须区分来源、发布时间、抓取时间、适用版本、可信度和交叉验证状态。模型既有知识不能替代最新情报源或目标环境验证。

## 核心领域对象

| 对象 | 作用 |
|---|---|
| `SecuritySignal` | 原始或归一化安全信号 |
| `Finding` | 已关联资产、来源和证据的风险发现 |
| `ThreatHypothesis` | 可验证的攻击、暴露或恶意行为假设 |
| `Incident` | 需要调查、协调和处置的安全事件 |
| `Campaign` | 跨事件、资产或时间范围的关联活动 |
| `Evidence` | 日志、快照、样本摘要、验证结果和人工记录 |
| `ResponseAction` | 通知、隔离、阻断、凭据轮换、修复或恢复动作 |
| `Playbook` | 版本化、可审批、可回滚的响应流程 |
| `DetectionRule` | 检测规则及其测试、版本和回滚状态 |

## 常驻闭环

```text
持续采集与归一化
  -> 去重、关联、资产和上下文补全
  -> 风险排序与威胁假设
  -> 只读调查和证据收集
  -> 调用安全评估智能体受控验证
  -> 事件判断与响应计划
  -> 低风险自动处置 / 高风险审批或人工接管
  -> 处置效果验证
  -> 规则、知识、漏洞状态和复盘更新
```

用户可以在任意阶段通过聊天：查询当前状态、查看证据、补充上下文、要求重新验证、批准动作、暂停任务、恢复任务或接管任务。聊天命令必须变成可审计控制面命令，不能直接修改事实源。

## 处置风险分级

- L0 观察：聚合、检索、报告和通知；
- L1 低风险：标记、临时降噪、创建工单、增加采集或隔离测试副本，可按策略自动执行；
- L2 中风险：调整检测、临时限制、凭据轮换或业务影响可控的隔离，默认需要审批；
- L3 高风险：生产阻断、批量隔离、删除、不可逆变更或大范围业务影响，必须人工确认或 `manual_takeover`。

所有处置都要记录预期效果、影响范围、回退/补偿方式、不可恢复副作用和验证结果。禁止自主 hack-back 或向外部目标扩张。

## 常驻运行契约

安全运营任务由共享 Durable Long-Running Agent Runtime 托管，必须有心跳、租约、预算、授权期限、重启恢复、事件归档和紧急停止。模型、规则、情报源或工具版本变化时，任务要记录版本并按策略重新验证，不得静默改变运行语义。

## 验收标准

- 后台任务可以在进程重启后恢复状态、证据和待办动作；
- 每个 Finding、Incident 和 ResponseAction 都能回溯来源和证据；
- 最新漏洞情报不会直接变成处置命令，必须经过匹配和验证；
- 安全评估调用绑定有效授权和范围；
- 高风险动作可暂停、审批、取消和人工接管；
- 处置后有独立效果验证和失败升级；
- 规则、知识和 Playbook 更新有版本、测试、审批、回滚和审计记录。
