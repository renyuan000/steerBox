# 安全评估与漏洞研究智能体设计

## 文档定位

本方向负责授权安全评估、漏洞研究、渗透测试、PoC 模拟验证和修复复测。它允许使用受控的模拟进攻方法，但产品边界是安全验证与风险降低，不是未授权攻击平台。

本文是长期领域设计。当前没有声明已实现自动渗透或漏洞挖掘执行链。

## 授权先于执行

任何主动验证任务必须绑定不可为空的 `AuthorizationContract`：

```text
authorization_id
authorized_by
target_scope
excluded_scope
valid_from / valid_until
allowed_tools
rate_limit
environment_boundary
stop_conditions
data_handling_rules
approval_ref
```

授权过期、目标不在范围内、工具不在允许集合、停止条件触发或环境边界无法证明时，任务必须停止或转人工，不得自动扩大范围。

## 能力分层

1. **被动分析**：代码、依赖、配置、镜像、SBOM、日志和资产暴露面分析；
2. **受控发现**：在授权范围内执行有限的攻击面和漏洞候选发现；
3. **隔离验证**：在靶场、快照或明确允许的测试环境中复现漏洞和模拟 PoC；
4. **影响判定**：记录受影响版本、前置条件、可观测证据和不确定性；
5. **修复复测**：验证修复是否有效，并保留前后对比证据。

模型只能提出计划或候选结论；工具执行、目标选择、利用验证和报告结论必须受 `PolicyGate`、范围校验和证据要求约束。

## 任务闭环

```text
授权和范围登记
  -> 目标与环境确认
  -> 被动分析
  -> 候选发现
  -> 人工/策略批准的受控验证
  -> 证据、影响和置信度评估
  -> 修复建议与责任分派
  -> 修复复测
  -> 归档与知识晋升
```

每次工具调用都要关联 `TaskRun / Attempt`、授权、目标、输入摘要、输出摘要、证据引用和 `SideEffectLedger`。敏感利用细节应按数据分级保存，默认不进入普通对话或跨任务记忆。

## 与其他方向的协同

- 软件开发智能体可提交代码、依赖或配置评估任务；
- 安全运营智能体可提交最新漏洞情报匹配和受控验证任务；
- 持续运维智能体可提交暴露面、配置和变更风险评估；
- 评估结果通过 `Finding`、`Evidence`、修复任务和复测结果回流，不直接触发无限权限处置。

## 安全边界

明确不做：未授权扫描、开放式利用、跨边界横向扩张、窃取凭据、持久化后门、面向外部目标的自主攻击或 hack-back。长期运行只表示维护研究队列和授权内的验证任务；每个主动任务仍需独立授权、有效期和停止条件。

## 验收标准

- 无授权或授权过期时主动工具调用被拒绝；
- 目标范围、排除范围和环境边界能被审计；
- PoC 验证在隔离或明确授权环境中执行，并留下证据；
- 高风险步骤可暂停、人工接管和紧急停止；
- 结论包含来源、证据、置信度、影响范围和待验证项；
- 修复后可复测，前后结果可比较；
- 任务重启后不会丢失授权、证据和副作用状态。
